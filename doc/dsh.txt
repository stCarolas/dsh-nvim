*dsh.txt*   DeepSeek Harness inside Neovim

==============================================================================
dsh.nvim                                                            *dsh.nvim*

Browse the DeepSeek Harness (`dsh`) sessions of the directory you are working
in, read their history in a buffer, send prompts, with the agent's reply
streaming into the buffer over DSH's WebSocket, and answer the agent's
questions and approval requests through |vim.ui.select()|.

Requires Neovim 0.10+, `curl`, and either `dsh` on `$PATH` or `npx`.

The plugin starts its own `dsh web` process with `--port 0` and stops it when
Neovim exits. `shared = true` makes every Neovim instance use one detached
server instead, and `url` attaches to a server you run yourself; see
|dsh-shared|.

Setup: >lua
    require("dsh").setup({})
<
Each session view is a scratch buffer named after the DSH session title, for
example `dsh://Fix the flaky retry test`. Before DSH titles a session the name
is `dsh://<short id>`. The name follows retitles, and a duplicate title gets
the session id appended, e.g. `dsh://Fix the flaky retry test (1a2b3c4d)`.
The `dsh://` scheme keeps the title from being read as a file path relative to
the cwd.

Session views and prompt buffers are unlisted ('buflisted' is off): they never
appear in |:ls|, |:bnext| / |:bprevious|, or bufferline-style lists. Use
|:Dsh|, |:DshSessions|, |:DshNextChat| or |:DshMenu| to switch sessions.

==============================================================================
COMMANDS                                                        *dsh-commands*

:Dsh                    Open a session: the current one, or pick one in the
                        current session scope.
:DshNew                 Create a session in the selected workspace (or this
                        directory's) and open it.
:DshNew!                Create a session, then open the prompt.
:DshQuickChat [mode]     Create a session in a chat mode, open its view in
                        a split and the prompt in a second split, prefilled
                        with the Visual selection. See |dsh-quick-chat|.
:DshNextChat            Switch to the next open session view; from a buffer
                        that is not a session view, create a session and
                        open its prompt.
:DshSessions            Pick a session in the current session scope.
:DshMenu                Nested menu: new session, open session, skills,
                        commands.
:DshModel               Pick the model of the current or chosen session.
:DshMode                Pick an Agent mode: this blank session's preset, or
                        the preset new sessions compose.
:DshWorkspace           Pick the Workspace that session pickers and
                        |:DshNew| use.
:DshWorkspace!          Return the session scope to Neovim's current
                        directory.
:DshPrompt              Open the prompt for the current session.
:DshSearch [scope]       List the session buffer's prompts, replies, tool
                        calls, errors and notices and jump to the chosen
                        one. `scope` is "all" (default), "prompts",
                        "replies", "tools" or "notes". See |dsh-search|.
:DshRefresh             Re-open the stream and re-read history.
:DshOutputToggle        Show or hide the tool output of the session buffer.
                        The `  ⚙ name(args)` call lines stay; each result
                        body collapses to one "… N lines hidden" marker, and
                        a failed result keeps its output. The state is per
                        view and starts from `show_tool_output`; see
                        |dsh-output|.
:DshToolsToggle         Show or hide whole tool exchanges — the
                        `  ⚙ name(args)` call line and its output — in the
                        session buffer, so it reads as the conversation
                        alone. A run of calls collapses to one "⚙ N tool
                        calls hidden" line that still counts failed results.
                        The state is per view and starts from
                        `show_tool_exchange`; see |dsh-tools|.
:DshCancel              Cancel the running turn; like |:DshInterrupt| but quiet.
:DshInterrupt           Interrupt the running turn of the session in view.
                        Works from a prompt window, a code buffer or another
                        tab: the session view under the cursor wins, then the
                        most recently used open view. The accepted request is
                        reported with the session title when known.
:DshClose               Close the session view.
:DshDelete              Delete (archive) the current session.
:DshDelete!             Same, without the confirmation prompt.
:DshWarmup              Boot or attach the server and wait until it answers.
:DshWarmup!             Same, then exit 0 on success and 1 on failure (for
                        startup scripts).
:DshStop                Stop the DSH server (shared or private).
:DshStatus              Show server, WebSocket and question status.

|:DshNextChat| cycles the open session views in buffer-number order (the
order they were opened), wrapping from the last back to the first. A view
whose window was closed or reused for another buffer is shown again where
`chat.open_in` says. From a buffer that is not a session view it creates a
session in this directory's workspace, opens it where `chat.open_in` says,
and opens its prompt (the |:DshNew!| path).

QUICK CHAT                                                    *dsh-quick-chat*

:DshQuickChat [mode] is the one-step path for "start talking to DSH about
this code". It

  1. creates a session in the current session scope, composed with the Agent
     mode named by the optional argument or by `quick_chat.mode` (default
     "chat"). The preset travels on `session/create`, which DSH resolves
     before it mints the session, so the first turn already runs in that
     mode. A mode the deployment does not publish is not fatal: creation is
     retried without it and a warning lists the ids the deployment does
     publish (built-in: standard, ptc, minimal, cordis; set
     `quick_chat.mode = nil` to stop asking for one);
  2. opens the session view as a horizontal split, leaving the code above it;
  3. opens the prompt as a vertical split of that view's window, so the chat
     and the input line share one band. Submitting closes the prompt and the
     view expands back;
  4. copies the Visual selection that was active into the prompt, with its
     file name, line range and filetype: >text
        lua/dsh/init.lua (lines 60-63):
        ```lua
        function M.open(session_id)
          ...
        end
        ```
<
     Both `:'<,'>DshQuickChat` (pressing `:` in Visual mode) and a plain
     :DshQuickChat after leaving Visual mode read the same `'<` and `'>`
     marks. The marks are buffer-local and only the current buffer is read,
     so run the command from the buffer holding the selection.

`quick_chat.selection` controls the prefill: `enabled = false` turns it off,
`reference = false` drops the file line, and `max_lines` (200 by default, 0
for no limit) caps it — a truncated selection says how many lines were left
out. `quick_chat.chat` and `quick_chat.prompt` choose the orientations and
sizes, independently of `chat.open_in` and `prompt.open_in`, which keep
applying to |:Dsh|, |:DshNew| and |:DshPrompt|.

`require("dsh").quick_chat({ mode = "ptc" })` is the Lua entry point, and
`keymaps.global.quick_chat` maps it. See |dsh-config|.

==============================================================================
SHARED SERVER                                                   *dsh-shared*

One `dsh web` serves many clients, so Neovim instances can share it instead
of booting one per instance.

With `shared = true` the first instance starts the server detached and records
its URL and launch token in `stdpath("run")/dsh-nvim/server.json` (file mode
0600 in a 0700 directory); later instances attach and mint their own peer
cookie. The shared server keeps running when Neovim exits, and |:DshStop| in
any instance stops it for everyone. `shared_dir` changes where the registry
and log file live.

To attach to a server you run yourself (systemd, tmux, the web UI), set `url`
to the URL printed by `dsh web`, including its `?token=...` query. The plugin
then only connects: it never starts or stops that server, and
`auto_start = false` still allows the attach.

Warm the server up once from a startup script so the first session opens
instantly: >

    nvim --headless -c 'DshWarmup!' >/dev/null 2>&1
<
It exits 0 when the server answers and 1 on failure. Warming up needs
`shared = true` or `url`; a private server stops with the Neovim that started
it. Without the bang, |:DshWarmup| waits, reports the URL, and leaves Neovim
running.

Every instance sees the same DSH sessions (subject to `sessions.scope`).
Human interactions are forwarded to every answering client, so with the web UI
or several Neovim instances connected, each shows the same question or
approval and the first answer settles it. Set `interactions.enabled = false`
in instances where those prompts should not appear.

KEYMAPS                                                          *dsh-keymaps*

Buffer-local, inside a DSH chat buffer:

    <CR>                    Open the prompt
    R                       Re-open the stream
    <localleader>s          Pick another session
    <C-c>                   Cancel the running turn
    q                       Close the view

`keymaps.output` is unmapped by default; set it — e.g.
`output = "<localleader>o"` — to toggle tool output (|:DshOutputToggle|)
from the buffer. `keymaps.tools` does the same for whole tool exchanges
(|:DshToolsToggle|), e.g. `tools = "<localleader>t"`. See |dsh-tools|.

In the floating prompt popup:

    <C-s>                   Send (normal and insert mode)
    <CR>                    Send (normal mode)
    <Esc>                   Cancel (normal and insert mode)
    q                       Cancel (normal mode)

Enter inserts a newline in insert mode, so prompts may span lines.

With `prompt.open_in = "split"` the prompt is a scratch buffer in its own
window instead of a popup. It edits like any other buffer: <Esc> keeps its
normal buffer meaning (leaving insert mode), <C-s> sends from either mode,
and normal-mode `q` cancels (as does closing the window, `:q`) — <Esc> never
dismisses the window. The buffer is named `dsh://prompt/<n>` and has
`filetype=dsh-prompt`.

Closing the prompt returns to the session view in normal mode. After a send
the cursor is placed on the newest line, so streamed output keeps scrolling
into view.

Global keymaps can be configured with `keymaps.global`; see |dsh-config|.
`keymaps.global.interrupt` maps |:DshInterrupt|, so a running turn can be
stopped from a prompt window or any other buffer. `keymaps.global.next_chat`
maps |:DshNextChat|, and `keymaps.global.quick_chat` maps |:DshQuickChat|.
`keymaps.global.model`, `keymaps.global.mode` and `keymaps.global.workspace`
map |:DshModel|, |:DshMode| and |:DshWorkspace|. `keymaps.global.output` and
`keymaps.global.tools` map |:DshOutputToggle| and |:DshToolsToggle|, which
act on the view at the cursor or the most recently used one, so the toggles
are reachable from a prompt window, a code buffer or another tab.

STATUS API                                                    *dsh-status-api*

For statusline plugins, `require("dsh").status()` returns one table of
connection facts: >lua
    local status = require("dsh").status()
<
It reads cached state and probes the recorded process id only; it never
starts the server, sends a request or opens a socket, so it is safe to call
on every redraw.

    running         boolean       the plugin holds server credentials
    connected       boolean       those credentials are usable (the server
                                  is not known to be dead)
    server_live     boolean|nil   recorded server process is alive; nil when
                                  it cannot be checked (attached mode)
    starting        boolean       a server boot or attach is in progress
    mode            string|nil    "own", "shared" or "attached"
    url             string|nil    server base URL
    pid             integer|nil   server process, when known
    websocket       boolean       multiplexed live-update socket is open
    stream          boolean       alias of `websocket` (compatibility)
    interactions    boolean       question/approval stream is ready
    views           integer       open session views
    error           string|nil    last connection error

`require("dsh").connected()` is the boolean shorthand for
`status().connected`.

==============================================================================
MENU                                                                *dsh-menu*

:DshMenu (or a `keymaps.global.menu` mapping) opens a nested |vim.ui.select()|
menu with four entries:

    new session             Create a session in this directory's workspace
                            and open it.
    open session…           Pick one of this workspace's sessions, the same
                            filtered list as |:DshSessions|.
    dsh skills…             List the session's human-invocable skills
                            (`skills/list`). Choosing one opens the prompt
                            prefilled with `/skill-name `; type the task and
                            send it, and DSH injects the skill instructions on
                            that prompt.
    dsh commands…           List the session's slash commands
                            (`commands/list`). A command advertising input
                            asks for it with |vim.ui.input()|; the line then
                            runs through `commands/execute`; its result text
                            is notified.

Skills and commands are session-scoped. The menu resolves its target session
when it opens: the view at the cursor, or the most recently used view still
open in another tab or window, so the catalogs open directly when a session
is already open. Only when no view is open at all does it offer the session
picker first, open the chosen session, and continue with the submenu. <Esc>
cancels any level.

==============================================================================
WORKSPACES                                                     *dsh-workspace*

DSH groups Sessions under Workspaces, the project rows the Web sidebar shows.
By default the plugin scopes session pickers and |:DshNew| to the directory
Neovim runs in. |:DshWorkspace| reads DSH's live `workspace/follow` roster and
makes the chosen Workspace the plugin's session scope:

- |:DshSessions|, |:Dsh| and the menu's "open session…" list that
  Workspace's Sessions;
- |:DshNew| and |:DshNew!| create their Session inside it;
- `sessions.scope = "all"` is overridden while a Workspace is selected.

The roster carries each Workspace's Session count and stays live as Sessions
join it; the count keeps an archived Session's slot until it is restored. The
first picker row returns to Neovim's current directory; |:DshWorkspace!| does
the same without a picker.

Selection is client-side: it never changes Neovim's working directory, file
paths or LSP roots, and it is not persisted beyond the Neovim session.

==============================================================================
MODEL AND MODE                                              *dsh-model-mode*

:DshModel and :DshMode are flat |vim.ui.select()| pickers over the catalogs
the DSH Web UI uses. Cancelling either changes nothing.

:DshModel reads `session/modelCatalog` and lists every routable model as
"Provider · Model — description". The current model is marked; a blank
session marks the deployment default. Choosing a model switches it with
`session/selectModel` and starts at that model's advertised default reasoning
effort. The target session is the view at the cursor, then the most recently
used open view; with no view open, the session picker runs first (and an
empty workspace creates a session to act on).

:DshMode reads `agentPresets/list` and lists the Agent presets the deployment
composes. Built-in ids use the Web UI's names: `standard` is Standard mode,
`cordis` is Creator mode, `ptc` is PTC mode and `minimal` is Minimal mode.
A preset declared by a bundle keeps its own name and description. On a blank
session (no turn has started yet) the choice applies to that session with
`agentPresets/select`. DSH fixes a session's composition once its first turn
starts, so from a started session — or when no session view is open — the
choice writes the preset new sessions compose instead, through
`settings/update` in the `agent-preset-registry` namespace. The picker prompt
says which case applies.

==============================================================================
QUESTIONS AND APPROVALS                                       *dsh-questions*

While a session view is open, the plugin answers the human decisions DSH
forwards to connected clients. Both kinds use |vim.ui.select()| and
|vim.ui.input()|, so any installed `vim.ui` provider works unchanged.

`ask_user_question` tool calls ~
    Each question opens one picker:
    - option rows show the option's description when DSH sent one;
    - "Other…" asks for free text with |vim.ui.input()|;
    - a multi-select question keeps prompting until "Done selecting";
      chosen options are marked ✓ and selecting one again toggles it off;
      free text supplements those labels;
    - "Skip this question" sends a blank answer (`selected = []`); <Esc>
      skips too, or finishes a multi-select with what is already chosen;
    - several questions in one call are asked in order and submitted as one
      answer batch.
    A question's long `detail` (for example a plan under review) is shown in a
    notification before the picker, because a picker prompt is one line.

Tool approvals ~
    "Allow once" / "Reject". <Esc> rejects, failing closed, the same choice
    the DSH Web approval panel makes.

A shared DSH server forwards every interaction to every connected client. The
plugin only prompts in the Neovim instance that shows the interaction's
session; other instances leave it to that one. An interaction that arrives
before its session is opened here is held and surfaces when the view opens, so
opening the blocked session still lets you answer it.

The prompts ride the same multiplexed WebSocket as the live session. They
become available with the first session view and stop with the last one. A
question asked while no view is open is delivered by DSH when the next view
connects. A timed question is claimed while its prompt is open, so the model
does not time out mid-decision; an answer given after DSH released the wait
arrives as a follow-up turn. See `interactions` in |dsh-config| to turn either
kind off.

CONFIGURATION                                                     *dsh-config*

All keys are optional; defaults shown. >lua
    require("dsh").setup({
      cmd = nil,                -- nil => {"dsh"}, else {"npx","--yes","@deepseek-ai/dsh@latest"}
      port = 0,                 -- 0 => OS-assigned
      cwd = nil,                -- server cwd (default: Neovim cwd)
      auto_start = true,
      url = nil,                -- attach to a running server (URL incl. token)
      shared = false,           -- share one detached server across instances
      shared_dir = nil,         -- registry/log dir (default: stdpath("run")/dsh-nvim)
      startup_timeout = 120000,
      request_timeout = 60000,
      max_messages = 200,
      sessions = {
        order = "oldest",       -- "oldest" | "newest" | "none"
        scope = "cwd",          -- "cwd" | "all"
        include_subagents = true, -- false => root sessions only
        include_archived = false, -- true => include deleted sessions
      },
      tool_output_lines = 8,    -- tool output rows shown as a code block
      show_tool_exchange = true, -- start views with tool exchanges shown
      show_tool_output = true,  -- start views with tool result bodies shown
      stream = {
        enabled = true,         -- false => read history once over HTTP
        render_interval = 60,
        reconnect_attempts = 5,
        reconnect_delay = 1500,
      },
      show_reasoning = false,
      treesitter = true,        -- register/start the bundled dshchat parser
      markdown = {
        enabled = true,         -- render agent output as Markdown
        code_highlight = true,  -- treesitter inside fenced code
        show_language = true,   -- fence language as virtual text
        max_highlight_lines = 300,
      },
      chat = {
        open_in = "split",      -- "split" | "tab" | "current"
        split = "vertical",     -- orientation when open_in = "split"
        width = 100,
        height = 20,
        show_title = true,      -- session title as the first buffer line
      },
      prompt = {
        open_in = "float",      -- "float" (popup) | "split" (buffer window)
        split = "horizontal",   -- orientation when open_in = "split"
        width = 80,             -- columns for "vertical"
        height = 10,            -- rows for "horizontal"
      },
      quick_chat = {
        mode = "chat",          -- Agent preset id (nil => deployment default)
        chat = { split = "horizontal", width = 100, height = 20 },
        prompt = { split = "vertical", width = 70, height = 10 },
        selection = {
          enabled = true,       -- prefill with the Visual selection
          max_lines = 200,      -- 0 copies everything
          reference = true,     -- prefix "<path> (lines N-M):"
        },
      },
      interactions = {
        enabled = true,         -- answer forwarded questions and approvals
        questions = true,       -- ask_user_question tool calls
        approvals = true,       -- permission prompts for sensitive tools
      },
      search = {
        scope = "all",          -- also: prompts, replies, tools, notes
      },
      keymaps = {
        prompt = "<CR>", refresh = "R", cancel = "<C-c>",
        sessions = "<localleader>s", close = "q",
        output = "",            -- e.g. "<localleader>o": toggle tool output
        tools = "",             -- e.g. "<localleader>t": toggle tool calls
        global = {},            -- e.g. { new_session = "<leader>dn",
                                --        next_chat = "<leader>dx",
                                --        interrupt = "<leader>di",
                                --        model = "<leader>dm",
                                --        mode = "<leader>dc",
                                --        workspace = "<leader>dw",
                                --        output = "<leader>do",
                                --        tools = "<leader>dt" }
      },
      notifications = true,
    })
<
`chat.open_in` selects where a session view opens: "split" (default), "tab"
or "current". With "tab", each session gets its own tab page, reopening
focuses the existing tab, and closing the view closes that tab. The legacy
spelling `split = "tab"` is still honoured.

`shared = true` uses one `dsh web` for every Neovim instance; `url` attaches
to a server you manage; `shared_dir` moves the shared registry. See
|dsh-shared|.

`chat.show_title = false` omits the `# Title` line at the top of the session
buffer; the winbar still shows the session title while the session is idle.

The winbar reads `dsh · <title> · <status>`. While a turn runs ("streaming"),
it replaces the title with the newest assistant message, clipped to the window
width; when the turn settles ("idle") the title returns. The buffer name keeps
the session title in both states.

`show_tool_output` sets what a new session view starts with: tool result
bodies shown (the default), or collapsed to one marker line per call. It is
the initial state of |:DshOutputToggle|, which then changes that view only.
`show_tool_exchange` does the same for whole tool exchanges — the call line
and its result — and is the initial state of |:DshToolsToggle|. See
|dsh-tools|.

`prompt.open_in` selects where a prompt is typed: "float" (default) opens the
centered popup, "split" opens a scratch buffer in its own window, which is
easier to edit long, multi-line prompts in. `prompt.split` picks that window's
orientation and `prompt.width` / `prompt.height` its size. A misspelled
`open_in` or `split` warns and falls back to the default instead of silently
keeping the popup.

`quick_chat` configures |:DshQuickChat| only: the Agent mode its sessions
compose, the two splits and the Visual-selection prefill. It never changes
where |:Dsh|, |:DshNew| or |:DshPrompt| put their windows.

Sessions are scoped to the selected Workspace, or to the directory Neovim
runs in when none is selected. |:DshWorkspace| switches that scope and
|:DshWorkspace!| clears it. :DshNew resolves the DSH workspace for the scoped
directory (registering it when it does not exist yet) and creates the session
inside it, so new sessions are grouped under the same project in the DSH web
UI. :DshSessions lists only sessions whose cwd is the scoped directory;
symlinked spellings compare equal because both paths are canonicalized with
`realpath` first.

`sessions.scope` controls that filter: "cwd" (default), or "all" to list every
session on the server; in "all" mode the picker prompt does not name a
directory. Any other value warns and falls back to "cwd". `sessions.order`
controls :DshSessions ordering. DSH itself returns sessions
most-recently-used first; the default "oldest" shows the least recently used
session at the top so stale work is easy to find. Use "newest" for the server
order, or "none" to keep whatever the server sends.

`sessions.include_subagents = false` hides sessions spawned by subagents
(`parentSessionId`, or `origin = "subagent"`), so pickers list only root
sessions. It applies to :DshSessions, :Dsh and the menu's session picker; the
default keeps subagent sessions in the list.

:DshDelete deletes the current session view. DSH has no hard delete, so this
uses its archive operation: running work stops, the session disappears from
the Web UI sidebar and from this plugin's pickers, and the transcript stays on
disk (unarchive it in the Web UI to restore it). Pickers hide archived
sessions by default; `sessions.include_archived = true` lists them again.
:DshDelete! skips the confirmation prompt.

If DSH creates the session and only then fails to attach it to the workspace,
the error carries the new session id: that session is opened with a warning
instead of creating a second one. Only errors raised before creation, or a
deployment without a workspace registry, fall back to a plain `cwd` session.

==============================================================================
MARKDOWN                                                        *dsh-markdown*

Assistant messages are rendered as Markdown; prompts you type are echoed
verbatim, because Markdown syntax there is your own text.

Rendered:
- ATX headings (`#` … `######`) — markers removed, styled by level
- bullet and numbered lists, nested by their source indentation
- task checkboxes (`- [ ]`, `- [x]`) as ☐ / ☑
- blockquotes with a `│` gutter
- horizontal rules as a line
- inline `code`, **bold**, *italic*, ~~strikethrough~~ and links
- fenced code blocks: fences are removed, code is indented by two spaces and
  grouped under |hl-DshCodeBlock|, with treesitter highlighting when the
  language parser is installed. The fence language appears as virtual text, so
  it never enters the buffer contents.
- tool results: kept verbatim as a code block tabulated one level under the
  `  ⚙ name(args)` call line (four spaces, |hl-DshCodeBlock|; a failed result
  keeps `DshToolError`), truncated to `tool_output_lines` rows, with the rest
  counted on a final line. |:DshOutputToggle| collapses these bodies and
  |:DshToolsToggle| folds the whole exchange; see |dsh-tools|.

Not rendered: tables are shown as source text, and `_italic_` is left alone so
snake_case identifiers survive.

Highlight groups are created with `default = true`, so any colourscheme or
|dsh-config| can override them: |hl-DshH1| … |hl-DshH6|, |hl-DshBold|,
|hl-DshItalic|, |hl-DshStrike|, |hl-DshCode|, |hl-DshCodeBlock|,
|hl-DshCodeLang|, |hl-DshLink|, |hl-DshQuote|, |hl-DshBullet|, |hl-DshHr|.

Set `markdown.enabled = false` to show the raw source instead.

==============================================================================
TOOL DISPLAY                                          *dsh-output* *dsh-tools*

Tool calls render as a `  ⚙ name(args)` line with the call's result as an
indented code block under it (see |dsh-markdown|). Such an exchange — the call
line and its output — can be folded away in two steps, each toggled per view:

|:DshOutputToggle| (or `keymaps.output`, once mapped) keeps the call line and
folds the result body: >

      ⚙ read(path=src/retry.ts)
        … 43 lines hidden
<
|:DshToolsToggle| (or `keymaps.tools`) is one level coarser and folds the call
line away with it, so the view reads as the conversation alone: >

      ⚙ 3 tool calls hidden, 1 failed
<
One muted line remembers how much is folded away. Toggling either again
restores the lines from the entries the view already holds; nothing is
fetched again.

|:DshOutputToggle| never collapses a failed result: its output, and its
`DshToolError` highlight, stay, because hiding a failure would hide why a
turn went wrong. A result with no output keeps its `(empty)` marker.

|:DshToolsToggle| folds failures too, but admits them: a run of hidden calls
appends ", N failed" to its summary and renders that line in `DshToolError`,
so a failure stays noticeable without the transcript it came with. The two
states are independent: hiding exchanges leaves the output state untouched,
so showing the exchanges again reveals the detail that view was left at
(call lines with collapsed output, for example).

Both states belong to the view, not to the session or the server: two session
views can disagree, and |:DshRefresh|, stream updates and retitles keep the
view as you left it. `show_tool_output` and `show_tool_exchange` set what a
new view starts with, so closing a view and opening it again returns to those
options. The winbar says which state is collapsed, as in
`dsh · <title> · <status> · output hidden` or `… · tools hidden`; when both
are collapsed the coarser marker wins.

Both toggles work from a prompt window or another tab too: like
|:DshInterrupt|, the session view under the cursor wins, then the most
recently used open view, and the change is reported with a notification.

The tool lines stay part of the buffer syntax either way, so |:DshSearch|
keeps listing each call — with its output when shown, with the hidden marker
when its body is collapsed, and as one "tool calls hidden" entry when whole
exchanges are folded. Folding an exchange also folds its failed result, which
is why the summary counts failures.

==============================================================================
SEARCH                                                            *dsh-search*

The session buffer is the whole transcript, so |:DshSearch| lists it as rows
instead of matching half a message at a time: the title, each prompt, each
reply, each tool call with its output, and the errors and notices DSH printed:

    You       fix the flaky retry test
    Assistant The retry loop copies the backoff value before the jitter …
    tool      read(path=src/retry.ts) 1 export function retry(fn, opts) {
    error     something failed

Matching runs over the whole message, so a word five lines into a reply is
found. Selecting a row puts the cursor on that message; `<Esc>` or `<C-c>`
leaves the cursor alone. The optional argument narrows the rows: >

    :DshSearch prompts
    :DshSearch tools
<
`search.scope` sets the default for |:DshSearch| without an argument, and
`keymaps.global.search` maps it, e.g. `{ search = "<leader>d/" }`.

Telescope renders the picker when installed (its `defaults` and
`layout_config` apply) and `vim.ui.select` otherwise, so telescope-ui-select,
fzf-lua, snacks.nvim or a plain prompt all work. A session view is a scratch
buffer with no file behind it, so there is no grep preview to show.

Rows come from the buffer: the session view under the cursor is searched,
else the session view in the current tab. Nothing is fetched from the server,
so a session that is not open is not searched.

==============================================================================
TREE-SITTER                                                   *dsh-treesitter*

The `dshchat` filetype has a bundled Tree-sitter grammar:
`tree-sitter-dshchat/` contains `grammar.js` plus the committed generated
`src/parser.c`, and `queries/dshchat/` contains `highlights.scm`, `folds.scm`
and `aerial.scm`. The grammar is line oriented: the first text line after a
header is typed `user_prompt` or `assistant_message_header`, later message
lines stay `text`, and each tool call groups its indented output.

With nvim-treesitter installed the parser is registered automatically, so >

    :TSInstall dshchat
<
builds it from the plugin checkout — no network access, and the `tree-sitter`
CLI is only needed to regenerate `grammar.js`. Without nvim-treesitter, build
it onto the plugin runtimepath instead: >

    scripts/build_parser.sh        # writes parser/dshchat.so
<
The renderer's extmarks still own the styling; Tree-sitter adds structure for
folds over rendered code and tool-output blocks, incremental selection and
`:InspectTree`, and its highlight captures reuse the same `Dsh…` groups.
`treesitter = false` turns the wiring off.

OUTLINE ~
`lua/dsh/outline.lua` groups a transcript into turns and
`lua/outline/providers/dshchat.lua` hands the tree to outline.nvim
(https://github.com/hedyhli/outline.nvim):

    Fix the flaky retry test            File
      fix the flaky retry test          Namespace
        I'll look at the retry loop.    Module
        Commands outputs                Object
          read(path=src/retry.ts)       Method
          edit(path=src/retry.ts)       Method
        The retry loop copies …         Module
        ✖ something failed              Event

Name the provider first in the priority list — a session buffer has no
language server, but another provider picking it first would win: >

    require("outline").setup({
      providers = {
        priority = { "dshchat", "lsp", "markdown", "treesitter" },
      },
    })
<
Entries are single lines of the transcript: the title, the first line of a
prompt, the first line of a reply, every tool call (marker stripped) and the
errors and notices the harness printed. A turn's tool calls are gathered
under one `Commands outputs` entry, so the command noise of a long turn folds
away with a single `<Tab>` instead of one per call.

Folding is outline's own: `<Tab>` toggles a turn, a reply or the commands
group, `h`/`l` fold/unfold, `W`/`E` fold/unfold everything. The default
`symbol_folding.autofold_depth = 1` opens the tree folded to turn titles, so
collapsing a prompt hides its replies and their commands;
`autofold_depth = false` opens it expanded.

`symbols.filter` selects by LSP symbol kind, not by transcript marker — the
provider emits `File` (title), `Namespace` (prompt), `Module` (reply),
`Object` (commands group), `Method` (tool call), `Event` (error) and
`Constant` (notice).

OUTLINE THROUGH AERIAL ~
`queries/dshchat/aerial.scm` uses the aerial.nvim query format, so aerial.nvim
shows the transcript, and outline.nvim's third-party
outline-treesitter-provider.nvim can read it too. That path is flat — the
grammar is line oriented, so no message node contains its tool calls — and the
provider only accepts a buffer when `queries/<lang>/aerial.scm` resolves.
Enable it in the outline setup: >

    require("outline").setup({
      providers = { priority = { "lsp", "markdown", "treesitter" } },
    })
<
The outline lists the session title, both turn markers, the first line of
every prompt and reply, every tool call, and the errors and notices the
harness printed. Multi-line blocks (`code_block`, `tool_exchange`) stay out of
it: an entry is labelled with the whole node text, so a block would render as
several sidebar lines.

HOW IT WORKS                                                        *dsh-design*

`dsh web` prints its URL with a per-process launch token, for example: >

    dsh web: http://127.0.0.1:3080/?token=...
<
The token is printed only in that line (shared mode records it privately for
other instances), so the plugin reads it from the process stdout and exchanges
it: >

    GET /connect?token=<token>&interactions=none
<
The answer sets a signed, authority-bound cookie. The long-lived HTTP peer
keeps `interactions=none`; the peer that owns a socket is minted separately
with `interactions=answer`, because only that kind may receive and answer
human decisions.

Unary calls use HTTP: >

    POST /api/<namespace>/<method>
    Cookie: <cookie>
    {"type":"client-request","rpcId":"…","method":"<namespace>/<method>",
     "payload":{"args":{…}}}
<
and answer with: >

    {"type":"server-response","rpcId":"…","result":{"ok":true,"value":{…}}}
<
Methods: `session/list`, `session/create`, `session/page`, `session/prompt`,
`session/cancel`, `workspace/create`.

Live updates use one multiplexed WebSocket at `/api/remote.mux`: >

    client -> {"type":"open","streamId":"nvim-1",
               "endpoint":"session/follow",
               "payload":{"args":{"request":{…,"assistantStream":true}}}}
    server -> {"type":"item","streamId":"nvim-1","value":{…}}
              {"type":"end"|"error","streamId":"nvim-1",…}
<
The first `item` of a follow stream is a snapshot (records, cursor,
projections, in-flight assistant stream); after it, durable events arrive as
`event` items and live token deltas as `assistant-stream` items.

Human decisions use the Gateway-owned `$events` stream on that same socket.
It starts with `{"type":"ready","clientId":…,"host":{…}}` and then forwards
`user-questions/request` and `approval/request` waterfall frames. The plugin
answers with a unary call: >

    POST /api/$events/result
    {"type":"client-request","rpcId":"…","method":"$events/result",
     "payload":{"args":{"clientId":"…","eventId":"…",
                        "outcome":{"kind":"result","value":{…}}}}}
<
Each forwarded frame names its Agent, and an Agent id is the Session id
(`agentId`). A shared server therefore delivers an interaction to every
Neovim instance, and the plugin prompts only in the one that shows that
session; other instances hold it until the session is opened there.

DSH only accepts the answer from the peer that owns the event stream, so this
call uses the socket's cookie, not the long-lived HTTP one. Answers decided
while the socket is down are held and flushed after the next `ready` frame.

`lua/dsh/ws.lua` implements the RFC 6455 client over |vim.uv| because Neovim
has no WebSocket client. DSH pings every 2 seconds and terminates a peer that
misses two pongs, so ping/pong handling is required, not optional.

Two DSH constraints shape this design:

- Unary methods cannot be opened on the stream carrier; DSH answers
  `gateway/signature-invalid`. HTTP therefore remains for unary calls.
- One authenticated peer may own one socket (a second upgrade gets 409), and DSH
  disposes that peer when the socket closes, so reusing its cookie answers 401.
  The plugin keeps a long-lived cookie for HTTP and mints a disposable peer for
  every socket; all session views share one multiplexed connection.

TROUBLESHOOTING                                              *dsh-troubleshoot*

Run |:checkhealth| `dsh` first.

- "no session cookie returned": the launch token was stale. The plugin mints
  its own token on every start, so this only appears if a fixed `port` is
  already served by another process with a different token.
- "websocket upgrade rejected": the cookie does not belong to the running
  server. `:DshStop` then reopening re-mints both.
- "live updates stopped": reconnect attempts were exhausted. `R` in the chat
  buffer retries; `:DshStatus` shows whether the socket is connected.
- A question or approval never appeared: its session has no open view in this
  Neovim instance (open it and a held interaction surfaces), the socket is
  disconnected, or `interactions.enabled` (or the specific
  `interactions.questions` / `interactions.approvals`) is false. `:DshStatus`
  reports the question stream; `:checkhealth dsh` shows the same.
- The same approval appeared in several Neovim instances: they all show that
  session. DSH broadcasts each interaction to every connected client, so the
  first answer wins; keep one view per session across instances.
- "timed out waiting for dsh web to start": the first launch may need to
  install the `web` profile. Run `dsh web` once in a terminal, or raise
  `startup_timeout`.
- Prompt is accepted but the answer is an error: the failure is rendered in
  the buffer. Configure a provider key in the DSH Models page or export it in
  the environment that launches Neovim.
